# Spec diff: Verfahrensbeschreibung DTA EEL V13.3 to V13.4

V13.3: 24.11.2025, valid from 01.01.2026. V13.4: 10.03.2026, valid from 01.01.2027.

Computed by a line diff of both PDFs (pdftotext, page headers removed, table-of-contents page numbers ignored), each change attributed to its data block and field. 67 raw changes, 36 after removing page-number shifts. **Field layouts (positions, lengths, types) are identical in both versions.** All changes are in the explanatory text.

**Why this file exists.** In production, the platform runs this diff itself whenever a new version is published (event A in `06_LIFECYCLE_AND_HIDDEN_TESTS.md`). We ran the same algorithm by hand once (`starter/tools/specdiff.py`) for three reasons:
1. **Proof of concept:** shows the approach works on real versions before we build it into the platform.
2. **Expected output (acceptance test):** task M5.1 must reproduce exactly these changes. Without knowing the right answer, we couldn't test the platform's diff.
3. **Demo design:** we needed to know which real change hits our scope. That's how we found the 6-month wording change and the `peter-gap-exact` case.

The platform does not read this file. It is seed data and the reference result for testing.

## 1. Changes that affect the prototype

| Block / field | V13.3 | V13.4 | Affects | Rule |
|---|---|---|---|---|
| **DBVO (3.12), chaining prior illnesses** | include a prior illness if "nicht **mindestens** 6 Monate" passed (gap < 6 months) | "nicht **mehr als** 6 Monate" (gap at most 6 months) | step 1 (41): which periods are listed and whether a 41 is required | R41-2, R41-3, parameter `gap_inclusive` |
| DSLW BBNR-VU (3.1.10) | no statement for replies | insurer replies carry the employer's BBNR-VU | steps 2, 4 (61 replies we generate) | K61-2 |
| DBID AKTENZEICHEN-VERURSACHER (3.19) | return unchanged | return unchanged, leave blank if the employer sent none | 61 replies | C-7 |
| DBSD VORNAME, FAMILIENNAME (3.20) | no explanation | must be the names in the cancelled record | step 5 (88) | C-4 |
| DBEE EEL-ENDE (3.7.3) | end of the paid period | if benefit continues after employment ends, only confirm up to the end of employment | step 7 (62 ends 31.03.2026 = end of employment) | C-6 |

The change log labels the DBVO change "redaktionelle Anpassung" (editorial). In practice it moves the boundary: a gap of exactly 6 months chains under 13.4 and did not under 13.3. Test case `peter-gap-exact` targets exactly this.

## 3. How the diff drives the test builder

```
changed passage (DBVO 3.12, chaining sentence)
  -> rules sourced from that passage: R41-2, R41-3
  -> rule parameter that changed: gap_inclusive false -> true
  -> test cases targeting R41-2/R41-3: peter, peter-gap-*, BP 13.2, BP 13.3
  -> recompute expected results under V13.4
  -> only peter-gap-exact changes (no 41 -> 41)
  -> draft: new expected files for peter-gap-exact, status "needs approval"
```
